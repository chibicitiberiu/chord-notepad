Every release at https://github.com/chibicitiberiu/chord-notepad/releases
carries two source files next to the downloads:

  ChordNotepad-<version>-source.tar.gz
      Chord Notepad itself, with its build scripts (chord-notepad.spec,

  ChordNotepad-<version>-third-party-sources.tar
      The source of every LGPL, GPL and MPL component listed here, for the
      Windows, macOS, Linux and Flatpak builds. For Windows it also holds the
      unmodified upstream FluidSynth package the DLLs come from. The Linux
      binary and the snap take their libraries from Ubuntu: the bundle holds
      the Ubuntu source packages of the GPL and LGPL ones and lists every
      Ubuntu package with its exact version; Ubuntu keeps every published
      source package at https://launchpad.net/ubuntu.

Using your own FluidSynth: the LGPL libraries (FluidSynth and the GLib,
libintl and libsndfile libraries it uses) are loaded at run time, not built
into Chord Notepad. To run Chord Notepad with your own build of them, set
the environment variable CHORD_NOTEPAD_LIBFLUIDSYNTH to the full path of
your libfluidsynth (on Windows, libfluidsynth-3.dll, with the DLLs it needs
in the same folder) before starting the app. This works with the Windows
download and the Microsoft Store edition, on macOS, with the Linux binary
and with the Flatpak (flatpak run --env=CHORD_NOTEPAD_LIBFLUIDSYNTH=...
--filesystem=<its folder>). The snap sets this variable itself: rebuild it
from the source above (snap/snapcraft.yaml) instead. Your build needs to be
FluidSynth 2.x. pyFluidSynth (LGPL) is part of the app's bundled Python
code: to change it, rebuild Chord Notepad from the source above (make build)
or run it from source.
