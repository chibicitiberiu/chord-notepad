  ChordNotepad-<version>-source.tar.gz
      Chord Notepad itself, with its build scripts (chord-notepad.spec,
      packaging/, .github/workflows/build.yml).

  ChordNotepad-<version>-third-party-sources.tar
      The source of every LGPL, GPL and MPL component listed here, for the
      Windows, macOS, Linux and Flatpak builds, Qt's and PySide6's source

      binary and the snap take their libraries from Ubuntu: the bundle holds
      the Ubuntu source packages of the GPL and LGPL ones and lists every
      Ubuntu package with its exact version; Ubuntu keeps every published
      source package at https://launchpad.net/ubuntu.

The Microsoft Store and Snap Store editions are built from the GitHub release
with the same version number: use that release's source files.

Using your own Qt or PySide6: the Qt window is drawn with Qt (LGPL 3.0)
through PySide6 and Shiboken6 (LGPL 3.0), as shipped in the PySide6-Essentials
6.12.0 wheels, unchanged. They are shared libraries that Chord Notepad loads
at run time, and Chord Notepad's own source and build scripts are in the
source file above, so you can use it with your own build of them:

  - Run it from source: in a Python environment with Chord Notepad's other
    dependencies (Pipfile) and your PySide6, run
    PYTHONPATH=core:desktop python -m chordnotepad_desktop
    in the source folder.
  - Build a package with them: install your PySide6 into the build
    environment instead of the wheel and run the same build (make build for
    the Windows, macOS and Linux downloads; with CHORD_NOTEPAD_ONEDIR=1 it
    makes a folder, with the Qt libraries as separate files), or build the
    Flatpak (make flatpak) or the snap (snap/snapcraft.yaml) from their
    manifests.
  - In the macOS app the Qt libraries are separate files under
    Chord Notepad.app/Contents/Frameworks/PySide6/Qt/lib. You can replace
    them with a build of the same Qt version, then sign the app again
    (codesign --force --deep --sign - "Chord Notepad.app").

The single-file Windows and Linux downloads unpack their libraries into a
temporary folder at every start, and the Microsoft Store edition, the
Flatpak and the snap are installed read-only, so for those use one of the
first two ways.

Using your own FluidSynth: the LGPL libraries (FluidSynth and the GLib,
libintl and libsndfile libraries it uses) are loaded at run time, not built
into Chord Notepad. To run Chord Notepad with your own build of them, set
the environment variable CHORD_NOTEPAD_LIBFLUIDSYNTH to the full path of
your libfluidsynth (on Windows, libfluidsynth-3.dll, with the DLLs it needs
in the same folder) before starting the app. This works with the Windows
download and the Microsoft Store edition, on macOS, with the Linux binary
and with the Flatpak (flatpak run --env=CHORD_NOTEPAD_LIBFLUIDSYNTH=...
--filesystem=<its folder>). The snap sets this variable itself: rebuild it
from the source above (snap/snapcraft.yaml) instead. Your build needs to be
FluidSynth 2.x. pyFluidSynth (LGPL) is part of the app's bundled Python
code: to change it, rebuild Chord Notepad from the source above (make build)
or run it from source.
